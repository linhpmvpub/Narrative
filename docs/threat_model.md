# P5 threat model — standalone offline backend

Scope: local source and test review of P0–P5 tooling, API, source adapters and dry-run dispatch, followed by the operational validation in `reports/operations-checkpoint.md`. SQLite and PostgreSQL regression, synthetic restore, Python dependency audits and loopback TLS controls are now validated. This is not an external penetration test or certification of an integrated production Threadnote deployment. No live data acquisition or notification channel was enabled.

## Assets, actors and trust boundaries

- Protect account credentials, private subscriptions/hypotheses/feedback, story sharing capabilities, database backups, source rights/provenance, immutable versions and replay results.
- Unauthenticated callers and ordinary members are untrusted. Members may submit adversarial text, identifiers, labels, cursors and repeated writes. Global operators have intentionally broader access and must be separately provisioned.
- Source documents and fixture text are data, including any instructions embedded in them. A source can be wrong, malicious, oversized, stale or corrected. A source approval is not blanket approval of every factual claim.
- HTTP requests cross bearer authentication and exact ownership checks before private reads/writes. Global operator actions cross a separate role check. There is no self-registration, client-selected role/tenant, cookie session or client-submitted graph approval identity.
- Trusted operator CLI/configuration and the database/filesystem are inside the current local trust boundary. Someone who can edit database rows, source caches or policy files can bypass application assertions. Production needs separate service identities, restricted storage and protected audit backups.
- Public sharing crosses a deliberate confidentiality boundary. The link is a bearer capability: anyone possessing an active link can read its limited factual preview. The user must explicitly opt in; rotating or disabling sharing revokes the prior lookup token.

## Threats, controls and remaining limits

| Threat | Implemented control / evidence | Residual boundary |
|---|---|---|
| Cross-user/tenant reads and writes | Server-resolved account identity; exact owner checks even within one tenant; foreign resources return 404; P4 ownership tests cover feed, unsubscribe, sharing, feedback and private narrative approval | Actual Threadnote SSO/tenant integration is unavailable; global operators are intentionally cross-tenant |
| Stolen/forged credentials or role escalation | Random 256-bit account bearer tokens, hashed storage, expiry/revocation, member/admin separation; API_TOKEN is catalog-only; no role fields accepted in requests | TLS, secure client token storage, operator MFA/SSO and credential rotation operations require deployment integration |
| Unicode credential crashes | Catalog secret comparison uses encoded bytes; malformed non-ASCII credentials return 401 in the new regression | Header parsing/protocol enforcement also depends on the ASGI server and ingress |
| Cached private stories and revoked share previews | Responses passing through API middleware set `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`; tests cover private/public reads, validation/auth errors, sharing and oversize rejection | Cannot erase previously downloaded content or control a client that ignores headers; redact share-token paths from access logs |
| Oversized/chunked JSON resource exhaustion | Middleware rejects bodies above 65,536 bytes before JSON parsing and validates Content-Length; tests cover missing, duplicate, malformed, understated and mismatched lengths plus exact boundary | This is not a rate/concurrency/time limit. Ingress must enforce headers/URL limits, request deadlines and connection limits. Expensive replay, repeated feedback and large observation histories still need operational quotas |
| SQL injection / arbitrary file operations | SQLAlchemy bound expressions; table names and admin fixture paths are server-selected; client requests cannot select replay files or execute shell commands | Operator CLI paths are privileged local inputs; filesystem permissions remain essential |
| Source prompt injection / executable markup | LLM_MODE=none; extraction schemas forbid extra fields and validate exact source spans; no document-driven tool calls or code evaluation; API returns JSON | External text remains untrusted text. A future UI must render it as text, not HTML; a future LLM integration needs a separate prompt/tool boundary and evaluator review |
| SSRF / redirect escape / hostile sources | SEC URLs are constructed from digit-only CIKs; IR uses exact HTTPS origin, no credentials/nonstandard ports, dated rights approval; redirects disabled; bounded retries, 15-second HTTP timeout and 5 MB decoded response cap; mocked adapter regressions | Generic SourceClient is an internal trusted primitive, not a public URL fetcher. DNS rebinding/private-address egress is not separately enforced; require network egress controls before live acquisition |
| Source cache or temporal tampering | Cached document and URL hashes checked; historical fetch is cache-only; graph revisions, narrative versions and metrics have as-of checks; evaluation manifests detect content changes | Local hashes are not signatures and cannot establish archive authenticity or original capture time against a privileged editor; append-only/protected archives and review are pending |
| Unreviewed financial citations | Story observations now reuse the relationship-review evidence gate: matching HTTPS document citation, nonblank reviewer, source offsets/claim, approved nonsynthetic source and clocks; source creation must precede cutoff | Approved-source status has no complete historical rights-revision ledger; current revocation fails closed but historical licensing reconstruction needs further design. No approved real financial feed exists yet |
| Feedback poisoning | Owner-only feedback, one active label with append-only prior rows, WRONG opens review, personal relevance never modifies source/edge truth; regression tests inspect unchanged candidate graph | Request rate/storage retention limits and operator review workflow are needed before public deployment |
| Duplicate/correction corruption | User-locked writes, idempotency receipts and unique keys; ingestion fingerprints, canonical reprint dedup, separate correction versions and linked immutable cards; retry/concurrency/correction suites pass on SQLite and PostgreSQL | Production workload stress testing, idempotency retention and capacity monitoring remain pending |
| Sharing private user notes | Default private, owner-only opt-in, opaque revocable token, factual allowlist excludes hypotheses/feedback/traces/IDs; P4 custom-story redaction tests | Raw share URLs are retained in idempotency response receipts to support retries. Treat database/backup access as access to share capabilities; do not describe all stored sharing data as hash-only |
| Unauthorized live delivery / synthetic leakage | Settings reject enabling notification/LLM flags; synthetic DB initialization is explicit and refuses existing real sources; planner checks gates, groups per-user versions, applies kill switch and enforces dry-run/null sent time | No real provider is installed. Any future sender must undergo a separate environmental, rights and authorization review |
| Evaluation leakage / misleading metrics | Complete case coverage, canonical/event-version/document split isolation, immutable manifest checks, source/narrative/edge/metric clocks, labels separate from inputs, B1 unavailable and missing metrics null | Human labels, archived sources and actual trace exports are not supplied; manual metadata/hash assertions are not independent validation. Pair confidence intervals do not imply independent events |
| Dependency/supply-chain compromise | Exact-version Windows/Linux Python inventories audited; pip patched; CI action commits and container image digests pinned | No OS-image audit, signed package provenance, wheel-hash lockfile or executed remote CI run is claimed |

## Changes made during this review

1. Added pure ASGI request-body limit and no-store/no-referrer/nosniff response headers in `engine/api/security.py`; wired it into the app.
2. Fixed catalog-token comparison for non-ASCII credentials and bounded catalog credential length.
3. Applied reviewed citation checks and source-creation cutoff to financial observations; rejected whitespace-only evidence reviewer IDs in the shared proof gate.
4. Added `tests/test_security.py` with boundary, privacy, credential, redaction and financial provenance regressions. Existing source adapter, ingestion, auth, feedback, sharing, temporal and dispatch tests remain part of the full verification.

## Failure recovery and operational requirements

- Keep the service bound to loopback/private infrastructure. Require TLS, explicit frontend origin policy, per-account/IP rate limits and bounded replay concurrency before internet access. Body size enforcement alone does not prevent slow or numerous requests.
- On suspected account leakage, revoke its token, provision a replacement through the trusted local account workflow, and review affected resources. A revoked account token does not automatically revoke previously shared public stories; revoke those separately when needed.
- Redact Authorization headers, feedback bodies and public-share tokens from application, reverse-proxy and tracing logs. Protect stdout when provisioning. Protect the DB, `.env`, source caches, evaluation labels and backup exports with least-privilege access; define retention/deletion and encryption policies.
- On failed writes, retry the same idempotency key/body. On a version conflict, review the current narrative and submit a new operation; never overwrite historical rows. Replay can resume partial per-user projection. Do not remove constraints to recover from a failure.
- A disposable synthetic PostgreSQL backup/restore drill matched all 36 tables, and migrations/concurrency regressions passed. Production encrypted/offsite backups, roles, retention and incident recovery remain separate required validation.
- Pin/review release dependencies and CI actions and run a vulnerability audit in the release environment. Treat the configured CI workflow as configuration, not proof of an executed remote run.

## Release conclusion

**NO_GO for production.** Local PostgreSQL, restore, dependency audit and loopback deployment evidence is recorded in `reports/operations-checkpoint.md`. External security testing, actual host integration, production operational controls and real historical evaluation remain pending. See `reports/release-v0.md` for the current gate list; earlier security checkpoints record their historical state.
